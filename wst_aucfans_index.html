From the SGH review

Questions, answered.

The thirteen technical questions raised during the SGH evaluation, with direct answers grounded in the WST architecture.

1Can one box hold many product IDs?

Yes. WST links product IDs and logistics IDs not only one-to-one, but one-to-many, many-to-one, and many-to-many through a parent-child structure.

Three product IDs (a bag, a wallet, an accessory) packed into one box receive a single box-level logistics ID — for example Box-001 containing IDs A, B, C. Scanning the box updates all child items; at delivery, each item can be marked delivered simultaneously.

  • Product ID — the brand's per-item ID
  • Box ID — the packing-unit ID created at shipment
  • Logistics ID — SGH's delivery & proof ID
  • Pallet ID — groups multiple boxes when needed
2No scanners today — what about field workload?

The PoC minimizes field load with a three-phase rollout, recording only high-value checkpoints rather than every micro-action.

Phase 1
QR / 2D barcode — handheld scanner, smartphone, or tablet via API to existing terminals
Phase 2
NFC — read the product or box NFC tag where present, link to the logistics event
Phase 3
RFID bulk read — Avery Dennison RFID gates read many boxes at once, lowering load long-term

Only shipment, pickup, hub arrival, loading, and delivery are scanned — the events with the highest proof value.

3Can LVMH and SGH choose what to share?

Yes — both sharing and non-sharing are supported, controlled by role-based access in the smart contracts.

Shared: product / DPP reference ID, logistics ID, box ID, status, pickup / arrival / delivery times, branch codes, transaction hash, delivery-proof ID.

Never on-chain: customer names, addresses, phone numbers, detailed contents, pricing, contracts, and driver personal data — these stay off-chain, with only hashes and reference IDs recorded.

4This works in Web2 — why own an L1?

Web2 can build tracking — but it ultimately means "trust SGH's database." On WST, each event is recorded in a tamper-evident form a third party can verify later by transaction hash.

The biggest benefit: SGH becomes the owner and standard-setter of its logistics data. Riding on someone else's chain makes SGH a data supplier; owning an L1 lets SGH design Japan's logistics proof layer on its own terms — with automated settlement and DPP interoperability Web2 can't offer.

5How is credibility established with LVMH?

Credibility rests on five pillars:

  • Permissioned PoA — only approved validators produce blocks; enterprise-manageable and auditable
  • Signed events — each scan carries device ID, branch ID, role ID, timestamp, and event type
  • No personal data on-chain — only minimal reference IDs and hashes
  • Clear role split — LVMH/Aura/Avery own product authenticity; SGH owns logistics proof
  • Auditable dashboard — SGH, LVMH, and auditors verify on-chain, not by SGH's word
6Beyond winning LVMH, where's the revenue?

LVMH is the entry point to a logistics-data business:

  • Premium "blockchain-proof" delivery for high-value goods
  • DPP logistics-proof API for brands, Aura, Avery, Deloitte, insurers, resale platforms
  • Insurance & dispute resolution using tamper-evident records
  • Paid audit reports for pharma, art, watches, jewelry, semiconductors
  • Corporate loyalty, driver rewards, and partner settlement via WST
  • Horizontal expansion to watches, apparel, pharma, food, spirits, cross-border EC
7What if competing carriers use SGH's L1?

That's the strongest outcome. If SGH opens the L1, it becomes the trust-infrastructure provider for the industry — not just a carrier.

SGH sets the standard, earns usage / API / proof-issuance fees, and gains leverage: brands using multiple carriers can verify them all against one standard. When regulators eventually require logistics, CO₂, temperature, and authenticity proof, the early standard-setter shapes the rules.

8What data can SGH analyze after the PoC?

Far more than LVMH and user ratings — a tamper-proof operational baseline:

  • Operations: pickup-to-delivery time, hub dwell time, missing-scan rate, exception rate, delay patterns, per-branch speed
  • Field load: time per scan, added worker burden, QR vs NFC vs RFID fit, label error rate
  • Business: which proofs LVMH values, premium pricing potential, API value, expansion fit
  • Technical: transaction volume, block speed, dashboard latency, node load, scaling needs
9Is horizontal expansion just adding servers?

Largely yes — server expansion plus per-industry app modules. The L1 base is shared; data fields, screens, and APIs are tuned per industry.

Infrastructure: start small, then scale to a 7-server (enterprise pilot) or 11-server (high-availability) configuration, adding validator / RPC nodes, indexer, explorer, backup, and monitoring.

Applications: luxury (DPP, authenticity, resale), pharma (temperature, lot, regulatory), food (origin, freshness), art (provenance), semiconductors (component authenticity).

10What apps are needed on top of the L1?

The L1 is the proof base; the field uses apps. The PoC builds these as one system:

  • Admin dashboard — status, scan history, on-chain records, exceptions
  • Scan-input app — QR / barcode / NFC / RFID → FME L1
  • Label-issuing app — logistics ID, box ID, QR / NFC / RFID labels
  • LVMH viewing portal — delivery status, proof, transaction hash
  • API layer — LVMH, Aura, Avery Dennison, Deloitte, SGH systems
  • Blockchain explorer — transaction ID, block, timestamp, hash
  • PoC reporting — history, exceptions, scan rate, proof export

12What exactly is the product ID?

A unique per-item ID assigned by the brand — for each bag, wallet, watch, or garment — potentially carrying brand, category, serial, lot, country, factory, materials, DPP reference, authenticity proof, repair history, ownership, and sustainability data.

It's read via QR, NFC, RFID, 2D code, Avery Dennison digital-ID labels, or Aura DPP tags. Where LVMH products already carry these, SGH doesn't create a new product ID — it references the existing one and links it to the SGH logistics ID. SGH's job is the logistics ID and the proof events.

13If the product ID proves authenticity, why a logistics ID?

They answer different questions. The product ID proves "this is a genuine LVMH item." The logistics ID proves "that genuine item travelled the right route, through the right hands, to the right recipient."

Product ID alone can't show when SGH collected it, which hubs it passed, which box it was in, which driver carried it, whether delay / damage / substitution occurred, who finally received it, or the point-of-liability for a claim.

Linking both on WST gives LVMH not just authenticity proof, but trust across the entire logistics process — the foundation for anti-substitution, insurance, resale history, and audit.
