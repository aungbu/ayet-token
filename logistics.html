CONCEPT

2つのIDが、2つのことを証明する

本システムの中核は、「商品ID」と「物流ID」を分けて管理し、両者を紐づけることです。

🏷️ 商品ID Product ID
正規品であること、シリアル番号、ブランド、DPP、ライセンス情報。ブランド側の既存デジタルID（RFID / NFC / QR）をそのまま参照でき、新規発行は不要です。
＝ 何であるか（Identity）
🚚 物流ID Logistics ID
集荷・拠点到着・積込・配達完了の各チェックポイント、封印状態、（必要に応じて温度・衝撃）。輸送の全過程を証跡として記録します。
＝ どう運ばれたか（Journey）
出荷登録 → 集荷 → 物流拠点到着 → 積込 → 配達完了
   ↓        ↓         ↓          ↓        ↓
 各チェックポイントの証跡を Layer1 に記録（改ざん不可）
   ↓
例外（封印異常・破損・ルート逸脱）も、隠せない記録として残る
OPERATION

1箱に複数商品でも、スキャンは1回

商品・箱・出荷を親子関係で管理。現場は箱を1回スキャンするだけで、中の全商品に同じ物流イベントが紐づきます。担当者が秘密鍵やウォレットを扱うことはありません。

商品ID A ／ 商品ID B ／ 商品ID C
        ↓
   Box ID / Carton ID
        ↓
  Shipment ID / 物流ID
RFID一括読取（将来フェーズ）では、期待数と検出数の照合により、開梱せずに欠品・混入を自動検知できます。
SERVICE MODELS

2つの補完的な追跡モデル

Model A — 標準物流証明
CHECKPOINT PROOF
  • QR / 2Dコードによるチェックポイント記録
  • スマホまたは一般的なハンディで運用
  • 重要イベントのみ Layer1 に記録
  • 既存の業務フローに追加するだけ
通常出荷・全商品向け
Model B — プレミアム・スマート追跡
RFID × IoT × GPS × L1
  • 固定式RFIDで通過を自動検知（手動スキャン不要）
  • IoTセンサーで温度・衝撃・開封を監視
  • GPSでルート逸脱をリアルタイム検知
  • 例外イベントを即時アラート＋チェーン証明
高価値品・ハイブランド向け
WHY LAYER1

「追跡」ではなく「証明」

荷物の現在地表示だけなら従来システムで十分です。Layer1が加えるのは、複数の会社をまたいで共有できる、改ざん不可能な証明です。

従来システム（Web2）
「当社のデータベースにそう書いてあります」— 記録した会社が後から変更でき、取引先はその会社を信じるしかない構造。
TrueLayer1（証明レイヤー）
「この時刻に記録され、その後変更されていないことを誰でも検証できます」— ブランド・保険・監査・二次流通が独立して確認可能。
世界の潮流
大手物流各社はRFID自動検知・IoT監視を既に実装。ただし記録は各社の非公開データベースにあり、独立検証可能な証明は提供されていません。
その先へ
検証済みの配達完了イベントを条件に、規制対応型の決済と接続する「証明→自動決済」まで拡張可能。支払いの前に、仕事の完了が証明される世界です。
